## Retained implementation

- `parse.js` constructs a default Parser before lexing, making its renderer
  available to the deferred inline phase. Lexer/Parser document state is new for
  each call. Importing this library does not configure V8.
- `fast-inline.js` renders the inline stream as it is lexed. Adjacent text stays
  buffered until the next non-text token, preserving marked's merging, numeric
  reference handling, and first-text-token escaping semantics. Non-image inline
  children are rendered strings, so they do not retain full token trees.
- Block lexing remains the original fork's algorithm. Deferred root inline
  arrays hold their rendered HTML in a per-document field, including any task
  checkbox prefix. Existing rendered prefixes are preserved if a queue array is
  visited again. Parser.parseInline accepts these results and string children.
- Image labels set a temporary flag in the original outputLink helper, restored
  with finally. Their children retain original marked tokens so TextRenderer's
  image-alt behavior remains exact, including nested images, code, and HTML.
- The normal GFM text regex remains the fallback for an entire inline source
  containing `@` or `&#`. Malformed email candidates and numeric references can
  make text segmentation observable. Other sources use a native search for the
  next possible construct; unmatched backtick/tilde runs are consumed together.
- Emphasis masks are built lazily from the complete original inline source,
  using the unchanged marked mask logic and closer cache, with finally cleanup.
  A conservative isolated-pair formatting shortcut requires plain content,
  whitespace/opening and closing boundaries, no possible autolink, and exact
  equality of the reference mask over the span and its preceding character.
  Complex emphasis, links, references, HTML, autolinks, URLs, and images still
  use marked's original tokenizers.
- `main.ts` uses the fixed V8 compiler-tier cap `--max-opt=1` through the built-in
  v8 API before rendering. This limits optimizing compilation work in the fresh
  one-CPU driver. There are no GC settings, environment-dependent choices,
  fingerprints, output tables, or cross-document output caches. The gain below
  is for this complete candidate, including the driver setting; it does not
  isolate an improvement from the streaming algorithm alone.

The marked 18.1.3 MIT notices and `vendor/marked` license/notice are retained.
The implementation remains ESM and dependency-free at runtime. The new Python
benchmark is a development tool and is not imported by the entrypoint.

## Discarded work and limitations

The first speculative direct subset was slower (seven-pair medians 0.780516
candidate versus 0.664140 submitted). Coverage measurement later found that an
all-or-nothing atomic inline subset covered only about 7% of inline characters.
Fused HTML-plus-plain-text arrays, a flat-list fast path, and a single-line
block shortcut did not show useful cold gains and were removed. A native scan
initially mishandled unmatched backtick runs and malformed email candidates;
the final scanner consumes complete runs and falls back to marked's text rule
for sources containing `@` or numeric-reference prefixes. Mask equality checks
were added after finding that malformed code inside links could hide later
formatting in marked's mask.

CLI-only runtime diagnostics did not establish that GC flags were safe to change
after startup. An actual-driver experiment applying `--single-threaded-gc`
through setFlagsFromString hit a native concurrent-marking assertion. That
setting was removed, and the aborted combined-setting timing run is excluded
from every retained result. Its first output comparison had read an older file
after the shell continued past the crash; it was invalidated immediately. All
subsequent actual-driver validation used exit-status checks and fresh output
directories. Only the compiler-tier cap remains in the driver.

All final correctness checks, fuzz runs, and retained timing batches completed.
No final-candidate CPU profile was collected after the compiler-tier change.
Earlier prototype profiles and optimization traces completed; a bounds-check
fix removed a second compilation of the streaming loop. No server grade or
submission was attempted. New scanner/representation paths still carry
compatibility risk beyond the tested inputs, and the fixed driver setting is
intended for the pinned cold Node 22 workload; a long-running host may prefer
its own optimization settings when importing `parse.js`.
